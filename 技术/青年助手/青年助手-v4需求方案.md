# 青年助手 v4 需求方案

背景：青年助手的历史设计记录；方案阶段以文档版本和正文说明为准。

> 在阅读正文中选中文本 → 加词 → 回注高亮。用户对材料的交互直接编辑自己的 markdown 副本。

---

### 核心设计

原材料不可变。用户第一次打开/加自选时，系统复制一份原始正文到用户的 `user_material.body_md`，以 markdown 存储。用户的加词、回注操作直接编辑这份 markdown：

```
原材料 body（不变）
  │  用户第一次打开
  ▼
user_material.body_md（用户私有的 markdown）
  │  段落 hover → [+] → 点选单词 → 确认列表 → AI 批量查义
  ▼
  body_md 自动更新：
  ├── 选中词包裹 **高亮**
  └── 所属段落后追加回注行
```

### 场景

**段落模式加词（主要方式）**

每个段落是一个独立的区块。鼠标移上后段落右侧出现两个操作按钮：

```
┌──────────────────────────────────────┐
│ This is a very challenging problem   │  [A]  [S]
│ that requires creative thinking.     │  ↑加词  ↑存句
└──────────────────────────────────────┘
```

- `[A]` → 加词模式，段落内每个单词变成可点选的按钮（见下方）
- `[S]` → 存句模式，调用 v8 的句子收集流程

点击 `[A]` → 段落进入**加词模式**，段落内每个单词变成可点选的按钮：

```
┌──────────────────────────────────────┐
│ This │ is │ a │ very │ [challenging] │  ← 灰色=未选
│ problem │ that │ requires │ [creative]│     蓝色=已选
│ thinking. │                           │
│                                      │
│   已选 2 个词    [确认添加]  [取消]     │
└──────────────────────────────────────┘
```

1. 用户点选单词（再次点击取消），每个单词独立选中
2. 选完后点击"确认添加" → 展示可编辑列表

```
┌──────────────────────┐
│  challenge            │  ← 每个选中词一行
│  creative             │
│  look                 │  ← 用户手动将多行合并为短语
│  forward              |
|  to                   │
│                       │
│  [点击行编辑文字]      │  ← 直接打字修改
│  [合并选中行]          │  ← 选中多行合并为一个短语
│  [拆分当前行]          │  ← 拆成多个词
│                       │
│  [确认添加]  [取消]     │
└──────────────────────┘
```

3. 用户自行调整：
   - 点击行编辑文字（改词形、修正）
   - 选中多行合并成短语
   - 拆分错合的行
4. 确认后 → AI 读取全文 + 段落上下文，批量判断词义
5. 返回每个生词/短语的音标、词性、释义
6. 批量处理：
   - 调用 v3 接口：批量创建生词+义项
   - 编辑 `body_md`：选中的词包裹 `**` 高亮，段落追加回注行

**选中文本（辅助方式）**
保留文本选中能力，主要用于存句（v8）和任务收集（v9），也可快速加单个词。选中后弹出操作菜单，菜单项根据当前模式变化：

```
选中文本 → 弹出菜单
            ├── 🔊 朗读              ← TTS 朗读
            ├── 📝 加词              ← 快速加单个（调 AI 查义）
            ├── 💾 存句              ← v8 句子收集
            └── 📋 提交到任务         ← v9 收集模式下出现
```

**回注渲染**

AI 处理 `body_md` 后效果：

```markdown
This is a very **challenging** problem that requires **creative** thinking.

**challenge** /ˈtʃæl.ɪndʒ/ n. 挑战
**creative** /kriˈeɪ.tɪv/ adj. 创造性的
```

展示时 `**` 渲染为高亮，回注行紧接段落下方。

### 数据

不再需要独立的 Annotation 表。用户的材料副本通过 `user_material` 存储：

```
UserMaterial
  ├── user_id: number
  ├── material_id: number       # 引用原始材料
  ├── body_md: text             # 用户私有的可编辑 markdown
  ├── status: 未读              # 未读 | 已泛读 | 已精读
  ├── is_favorite: boolean
  ├── is_want_read: boolean
  ├── annotated_words: number   # 已标注词数（缓存，快速展示）
  └── created_at: datetime
```

- 用户第一次加自选/打开材料时 → 从原始 `Material.body` 复制初始化 `body_md`
- 每次加词 → AI 编辑 `body_md` → 保存
- `annotated_words` 在加词时同步递增，方便材料卡片直接展示
