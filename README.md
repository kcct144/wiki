# YouthNote 知识库

这里保存学习、研究和项目思考的 Markdown 文档，由 AI 持续整理。它是独立 Git 仓库，保留在 YouthNote 的 `local/wiki/` 中，作为 AstrBot 向量知识库的内容源。Markdown 是唯一需要维护的正文；向量索引由 AstrBot 根据这些文档生成。

## 内容结构

按“主题／专题／文档”组织，主题表示领域，专题围绕一个研究方向或项目。通常保持三层；确有必要时可增加子专题。同一文档只放在主要归属处，跨专题关系通过引用表达。

```text
教育/
└── 学习方法/
    └── 间隔重复.md
艺术/
└── 摄影/
    └── 曝光三角.md
技术/
└── AI协作/
    └── 人机协作.md
.meta/                       # 管理记录和历史快照，不参与检索
README.md                    # 本约定，不参与检索
```

不再按概念、来源、实体等笔记类型分目录，不维护全库手写索引。材料摘记、综合认识和用户自己的想法都可以放在相应专题中，不要求将它们拆成几套平行页面。

## 编写原则

- 每篇文档有一个明确的一级标题，围绕一个问题、对象或材料展开。标题和小节名称应表达具体内容；长文按论点、步骤或案例分节，不为固定字数机械拆文。
- 正文应独立可理解。关键段落说清研究对象、条件和结论，少用脱离上下文就无法理解的“它”“上面”“这个”。链接用于关联，必要解释仍写在正文中。
- 清楚区分材料作者的陈述、用户观点和 AI 的综合解释。材料摘记可在标题中标明“材料笔记”；重要主张在相应段落注明归属。未经核验的数字、因果解释和推测保留其限定与不确定性，不把建议写成普遍规律。
- 出处写在正文中，可按需使用“出处”小节；保留网址、作者、相关日期、对话背景和材料位置。日期有明确含义再记录，例如材料发布日期或观点修订日期。来源不明就注明待核对，不补造网址或作者。
- 知识文档使用普通 Markdown，不新增 YAML frontmatter。需要检索的背景、别名和来源应出现在正文中，不只藏在元数据里。
- 库内引用使用相对 Markdown 链接，如 `[曝光三角](<曝光三角.md>)`，不用 `[[双链]]`。YouthNote 的 raw、post、docs 位置可写成出处，例如 `YouthNote/local/raw/.achieved/某材料.md`；文档理解不依赖这些库外文件。图片和链接里的内容不会自动变成被检索的正文，必要信息须另行写清。
- 合并重复信息并保留有意义的差异。修正认识时说明证据与适用范围，尚未解决的矛盾继续保留。历史方案须说明阶段，避免让旧设想看起来像当前已实现的功能。

## AstrBot 同步

使用 [astrbot_plugin_knowledge_repo_sync](https://github.com/Sakura1618/astrbot_plugin_knowledge_repo_sync) 同步这个独立仓库，而不是 YouthNote 主仓库。在插件设置中填写：

| 设置 | 内容 |
| --- | --- |
| `remote_repo_url` | 本知识库独立远端仓库的 Git URL |
| `remote_branch` | `main` |
| `target_kb_name` | 自己选定的知识库名称，例如 `YouthNote` |
| `ignore_paths` | `README.md`、`.meta` |
| `chunk_size` | 先用插件默认值 `512` 建立基线 |
| `chunk_overlap` | 先用插件默认值 `50` |

`ignore_paths` 按仓库相对文件或目录匹配，不是通配符。应填 `.meta`，而不是 `.meta/**`；Git 忽略规则不等于插件导入规则。

插件递归上传 `.md`、`.markdown` 文件，不解析 frontmatter，也不展开引用链接。核对的 AstrBot 源码会对 Markdown 使用标题分块，为子节添加父级标题背景；较长的小节再按字符分割。这里的分块长度按字符计算，不是 token。以上行为依据 [插件源码](https://github.com/Sakura1618/astrbot_plugin_knowledge_repo_sync/blob/d4e1e12e7e0d7da886506ed3711e52bc149cf099/main.py)、[AstrBot 上传逻辑](https://github.com/AstrBotDevs/AstrBot/blob/74465625ed441d89b4c33750763b15ed4ce677d3/astrbot/core/knowledge_base/kb_helper.py) 和 [Markdown 分块器](https://github.com/AstrBotDevs/AstrBot/blob/74465625ed441d89b4c33750763b15ed4ce677d3/astrbot/core/knowledge_base/chunking/markdown.py)；部署时确认所装版本的行为。

私有仓库的读取凭据应配置在 AstrBot 运行环境中，保证该环境能执行 Git 拉取；不要将凭据写进正文或仓库 URL。知识库须选择已配置好的嵌入模型，检索效果还取决于模型、分块和检索参数。

改名会被同步插件视为删除旧文档并新增文档。首次同步核对文档数量，确认 README 和 `.meta` 未被导入；日常更新通过独立仓库的提交、推送同步。

## 检索检查

用实际问题检查命中的片段是否包含完整论点、适用条件与可辨识的出处，不能只看回答是否流畅。可先试：“英语学习三个阶段分别做什么？”、“人像摄影中如何控制景深？”、“青年助手 v8 的句子功能有哪些？”；再测试跨文档问题和库中没有答案的问题。

若一个论点被分散在过短的块里，可试 `800` 字符、`80` 字符重叠，与默认设置比较。这只是调参起点。领域目录便于维护，不能替代实际检索评测；同步成功和格式正确也不代表召回质量已经验证。

## 仓库维护

在 `local/wiki/` 内执行本仓库的 Git 操作；YouthNote 主仓库忽略整个 `local/`，raw 仅保存在本地。重新克隆 YouthNote 时，raw 需从本地备份恢复，知识库远端需单独克隆到 `local/wiki/`。提交与推送按用户明确要求执行。

`.meta/` 保存必要的管理记录。首次迁移的路径对应关系、原始元数据及旧索引、日志仅作为历史记录保留，不作为持续同步的另一套内容或当前知识索引。
