# 问题分解

别名：分解问题、Problem Decomposition、拆解。

> 将复杂、看似无法解决的问题拆解为若干可解决的小问题。

## 核心思想

问题解决的难度与复杂程度正相关。任何看似不能解决的问题，都可以通过拆解降低难度。

关键区分：==分解不等于快速解决，而是给予行动的信心和方向==。

## 来源综合

### 源头定义（面对困难系列）

在困难应对框架中，分解是四种策略之首：[面对困难的四种策略](<2024-12-17 面对困难的四种策略.md>) 和 [面对困难的四种方法](<2025-05-31 面对困难的四种方法.md>) 都将其定位为"自己解决"的首选策略。核心前提：==任何困难都是可分解的。==

思维导图被推荐为分解问题的工具——可拖动节点便于重组思路。

### 拓展应用（学习的目的性）

[2025-05-24 学习的目的性](<2025-05-24 学习的目的性.md>) 将分解应用于学习规划：任何要解决的问题、学习的东西，都是可以分析拆解的。拆解后区分重点/次重点/非重点，避免"学得越多越迷茫"。

### 实践落地（笔记方法）

[2025-05-31 笔记方法](<2025-05-31 笔记方法.md>) 的五步法第 2 步"分析问题"正是分解的实践形式——多角度拆解、定位关键因素、追问根本原因。

### GRINDE的分组即问题分解

[2026-07-25 思维导图GRINDE法则](<2026-07-25 思维导图GRINDE法则.md>) 的 G（Grouping/分组归类）步骤本身就是问题分解的操作化呈现：**将相关概念归类，选择一种分组方式。**

GRINDE强调"关键不在于分组本身，而在于选择哪种分组方式"——这与问题分解的"任何困难都是可分解的"形成呼应：分组/分解不是一次性的技术动作，而是需要判断的认知策略。不同的分组方式产生不同的理解框架，而这正是贾斯汀·宋所说的——思维导图的价值不在成品，在创建过程。

### 跨领域：分解的停止规则（来自 AI Agent 工程）

[2026-07-19 Kilo AI Agent 工程哲学](<../../技术/AI协作/2026-07-19 Kilo AI Agent 工程哲学.md>) 为"拆到什么程度"提供了可操作的判据：

> **任务粒度应限制在审查者单次可评估的范围内。** 如果一个人没法在一次坐下来就评估完 agent 的输出，那这个任务就拆得太大了。

这一原则从 AI Agent 工程反哺到一般问题分解领域，补上了经典分解理论缺失的一环：**分解不是越细越好，细到可审查即可**。

| 领域 | 停止规则 | 粒度参考 |
|------|---------|---------|
| AI Agent 任务 | 单次审查能评估完 | 15-30 分钟可审查 |
| 学习计划 | 单次学习能完成并自检 | 一节课/一次自习 |
| 项目管理 | 单次迭代可交付验收 | 一个 sprint / 一个 story point |

## 与其他概念的关系

- **[主要矛盾](<主要矛盾.md>)** — 分解前需先识别主次，否则可能在次要问题上过度拆解
- **[目标导向学习](<目标导向学习.md>)** — 为分解提供方向锚点——拆解围绕"要解决什么问题"展开
- **[元认知](<元认知.md>)** — 监控分解过程是否有效、是否需要调整拆解粒度

## 工具推荐

- 思维导图（可拖动节点的软件）
- 优先级矩阵（能力范围内/外 × 主/次要）
- 量化目标拆解（如：进步 100 分 → 英语 +15 → 完型 +5 → 每天训练一套）

> [!assumption] 假设
> 人类面对复杂问题的第一反应是退缩（"这太难了"），而分解的核心作用是降低启动门槛。验证方式：对比两组被试面对同一复杂任务，一组接受分解训练，一组不接受，观察启动率和完成率。
